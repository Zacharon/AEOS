Two paths. One source of truth.

Project work returns through controller writeback. Knowledge promotion has a separate owner decision and Librarian apply gate.

Architecture / narrow-screen view

  1. Route and bound the work — MANUAL + CLI.

    Read the router and project facts. Scaffold a packet, then fill its scope, checks and actual authorization.

  2. Prepare context — CLI + MANUAL.

    Select cited files. handoff.py build saves a brief, snapshots and hashes; check checks integrity and source freshness.

  3. Work and return evidence — MANUAL.

    Give the bundle to your assistant. It uses authorized tools and returns a result, artifacts and actual checks.

  4. Review and write back — CLI + MANUAL.

    Validate the result and current sources. Obtain independent review when required and applicable owner decisions. The controller performs authorized project writeback.

  5. Promote knowledge separately — CLI + OWNER.

    Ingest source bytes into Bronze; propose and verify an authored candidate in Silver. Only an exact owner decision, covered Git checkpoint and fresh checks permit apply to Gold.

  6. Recover explicitly — MANUAL.

    Invalid, missing or stale evidence stops promotion. Preserve the old receipt, inspect the change and rebuild the authorized bundle. Pending or rejected knowledge stays outside Gold.

Solid paths are file operations or CLI checks. Dashed paths require a person or assistant. The source and candidate text must both be supplied; Librarian does not generate a synthesis. A worker's proposed writeback is a suggestion, never an automatic canonical update.

Saved truth and copied context

Canonical project records and Gold notes hold current facts. A handoff bundle contains selected snapshots. Checking their hashes tells you whether the source changed; it does not decide which contradictory statement is true.

Checks and permission

A passed structural check is candidate evidence. Independent review, an exact owner decision and release authorization remain separate. No result checker grants permission or authenticates the owner.

How someone actually uses AEOS

Plan → Retrieve → Execute → Verify → Learn. Each stage ends in a file another stage can inspect.

Five stages / narrow-screen view

  1. Plan — operator + assistant.

    Read current project facts; set scope and checks. Output: a bounded task packet.

  2. Retrieve — operator + local CLI.

    Select cited files; build and check the bundle. Output: snapshots with hashes. Give the selected files to the assistant manually.

  3. Execute — assistant + authorized tools.

    Complete the permitted task and bring back the result and real artifacts. Output: inspectable work and evidence.

  4. Verify — CLI + reviewer / owner.

    Validate the result and current source bytes; obtain required independent review and applicable owner decisions. If a check fails or evidence is stale or missing, stop, preserve the receipt and rebuild after inspection.

  5. Learn — authorized controller.

    Save factual project state and the next action. Useful knowledge goes through separate Bronze/Silver/exact-owner/Gold gates. A fresh session starts from the saved files and reruns review.

The five stages are a usage guide, not an installed scheduler. A manual assistant handoff can involve files or copying a bounded brief into another app. Adapter configuration does not authenticate a provider or start execution.

Proposed, outside the working path: automatic Wiki synthesis, scheduled model dispatch, live connectors and automatic learning.

ICM informs staged context selection. LLM Wiki informs cited, compiled knowledge. Neither influence is a separate installed background service. The public preview does not contain the personal OS's projects, history or private integrations.

Start with the synthetic first run

Follow the first-run guide for the documented prerequisites. From a fresh package extraction:

python -B scripts/check_package.py .
python -B scripts/demo.py --output ../aeos-first-run

Open ../aeos-first-run/START_HERE.md. The deterministic demo ingests a synthetic source, verifies a pending Silver proposal, uses selected evidence in a task and saves a result. It also checks refusal of stale and missing sources. It makes no AI call, independent-review verdict or Gold promotion.

Inspect verification and limitations before using valuable data.
